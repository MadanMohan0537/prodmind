# Product requirements

## Problem

Product teams often retain obsolete capabilities indefinitely or retire them using incomplete usage data. Neither path accounts reliably for critical cohorts, integrations, migration readiness, communication, ownership, or accountable approval.

## Requirements

1. Accept 1–50 lifecycle plans linked to a Project 20 journey.
2. Support retain, invest, consolidate, and retire as explicit human decisions.
3. Preserve upstream release and evidence lineage.
4. Require adequate notice, replacement readiness, migration guidance, dependency plans, communications, exit criteria, and cross-functional approval for sunset actions.
5. Fail closed on malformed, ambiguous, duplicate, or unbounded inputs.
6. Expose a protected Worker API and accessible light/dark UI.

## Non-goals

Automatic recommendations, contract interpretation, customer notification, migration execution, traffic changes, feature deletion, causal analysis, or revenue forecasting.

## Acceptance

The same snapshot produces the same report; blocked dependencies and rejected approvals prevent readiness; small-cohort details remain governed by Project 20; no caller can replace upstream lineage.
