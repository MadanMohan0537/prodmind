# Architecture

## Flow

1. Project 28 supplies verified recurrence surveillance and evidence lineage.
2. The validator derives actionable targets from recurrence counts and failed checks.
3. Candidate normalization verifies scope, ownership, dates, success measures, and dependencies.
4. A bounded exhaustive optimizer evaluates at most 65,536 subsets for 16 candidates.
5. The decision gate compares unique weighted coverage with the declared threshold.
6. The Worker returns a reviewable plan; no side effect changes controls or work systems.

## Determinism and tie-breaking

The optimizer maximizes unique target risk points. Equal-value solutions prefer lower effort, then fewer actions, then stable input order. The response exposes the method and combinations evaluated.

## Trust boundaries

- Bearer authorization is compared using SHA-256 digests.
- Cross-origin API requests are rejected.
- Request bodies are capped at 2 MB.
- Responses are not cached and include restrictive browser security headers.
- One deployment is for one trusted team; the token is not tenant isolation.

## Connected contract

Project 7 reconstructs Projects 18–28 server-side, then passes the resulting Project 28 report into `planControlImprovements`. Client IDs cannot replace the upstream governance, portfolio, exit-review, or evidence lineage.
