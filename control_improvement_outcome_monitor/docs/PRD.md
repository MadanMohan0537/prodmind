# PRD — Product Control Improvement Outcome Monitor

## Problem

Project 29 creates an approved improvement portfolio, but approval and task completion do not show that recurrence was reduced. Teams need a consistent evidence gate before closing improvement actions.

## Users and job

Product governance leads, control owners, engineering leaders, and product councils need to compare the approved plan with delivery records and later surveillance, identify incomplete verification, and record a named close, continue, or escalate decision.

## Requirements

1. Accept only selected actions from a Project 29 report.
2. Preserve original recurrence and customer-evidence lineage.
3. Validate completion, delivery evidence, actual effort, and success evidence.
4. Compare schedule and effort with the approved plan.
5. Require later Project 28 surveillance and the promised verification window.
6. Block close when evidence is incomplete, lineage breaks, or recurrence persists.
7. Expose an authenticated Worker API and responsive light/dark interface.

## Non-goals

- Closing tasks or changing controls
- Proving the action caused an observed change
- Creating monitoring data
- Scoring individuals or teams
- Replacing independent review
